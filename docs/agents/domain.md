# Domain docs

## Before exploring, read these

- Root `GLOSSARY.md` for domain vocabulary.
- ADRs in `docs/adr/` that concern the work.

If these files are absent, proceed silently. The `/domain-modeling` skill creates them when terms or decisions are resolved.

## File structure

Single-context: one root `GLOSSARY.md` and root `docs/adr/`.

## Use the glossary's vocabulary

Use glossary terms in issue titles, code, tests and proposals. If a concept is missing, reconsider the terminology or note the gap for `/domain-modeling`.

## Flag ADR conflicts

Surface any conflict with an existing ADR, citing the ADR and why the decision should be reconsidered.
